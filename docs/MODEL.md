# Swap stat model (`gdc::model`, Slice A)

`model::swap(snapshot, candidate, location, db)` removes the old item's own getter output, adds the candidate's, and re-derives the dependent numbers. `model::sheet()` reads the compared numbers from a real or a predicted snapshot. Item output already includes components, affixes and stat rolls (`docs/SNAPSHOT.md`).

## Rules and evidence

All checks below are within float rounding: fixture pair `lvl96-before/after-ring-swap` (finger 2: `c031_ring` → `b201e_ring`) and pair `lvl96-phase21-axe-hover` → `lvl96-swap-poison-ring-chest` (finger 2 + chest).

| Stat | Rule | Source / check |
|---|---|---|
| char attributes | `total = flat × (1 + modifier%)`, so flat = total / (1 + mod%); swap adds the items' `value` to flat and their `modifier` to mod | both pairs, types 1–7, 14, 21, 23 |
| Life / Energy from attributes | flat Life += 2.5 / Physique, 1 / Cunning, 1.5 / Spirit; flat Energy += 2 / Spirit, on attribute **totals** | `playerlevels.dbr` lifeIncrement 20, lifeIncrementDexterity 8, lifeIncrementIntelligence 12, manaIncrement 16 per 8 points. Spirit +12.1 checked; Physique/Cunning ratios not yet exercised by a fixture |
| regen, OA, DA | `formulas::*` on the predicted totals | `combat_formulas.h` |
| resists | raw = Σ; shown = min(raw + \|raw\|·mod%, defense_cap + cap_bonus) for types with a `DefenseAttributeDefenseCap_*` class | `CombatAttributeAbsDefense::Process` 0x115370; Poison 105 → 91, Disruption/Stun 80 |
| Absorption (39) | every armor entry carries `armorDefensiveAbsorption` (70), so the mean of positive entries is 70 while any armor exists, else 0; modifiers sum. The snapshot has a 39 row only once an absorption modifier exists | `GetTotalDefenseType` 0x11A880, `DefenseAttribute_BaseProtectionAbsorption::LoadFromTable` 0x204420 / `AddToAccumulator` 0x204BF0 (docs/MECHANICS.md §5); 70 / 70 → 70 |
| armor (sheet) | (Σ armor-slot item armor × region % + waist armor) × (1 + Protection mod%) | region % from `combatformulas.dbr`; 1407.78 vs sheet 1408. Waist term is a fit to that single value |
| run speed | type 14 total | cap (`Player::CapRunSpeed`) not modeled |
| item skill grants | Δ augmented level per skill: `augmentSkillName*` by record (`SetSkillLevelAugment` 0x5375B0), `augmentMasteryName*` to the mastery skill and every skill with that `mastery_id` (`SetMasteryAugment` 0x5373D0), `augmentAllLevel` to all (`SetAllSkillAugment` 0x537230; its one exclusion not traced → warning). Learned skills only: current = min(level + augmented, max(skillUltimateLevel, skillMaxLevel)) (`GetCurrentLevel` 0x4909C0, `SkillProfile::LoadProfile` 0x545A27). The skill's stats at the old and new level come from its record (per-level arrays at level − 1, one value = every level), mapped by `gdc::fields` (sources in `db_fields.h`). Only skills that contribute now: `skills[].passive` non-empty (schema 4), and that capture must equal the record at the current level or the skill is skipped with a warning. Schema < 4: `Skill_Passive` and `Skill_BuffSelfToggled` assumed on (warning) | ring pair: Possession 21 → 19, Chaos 34 → 32. Poison pair: `wpattack0` 5 → 2, Protection mod 9 → 5, sheet armor 1386 exact; Blood of Dreeg (`Skill_BuffRadius`, buff not running) 12 → 9 leaves OA unchanged |
| skill attachments | A skill's engine passive = its record at the current level + its **learned modifiers** (`skills[].modifier_ids`, Skill+0x140, schema 5) at their current levels + its **item skill modifiers** (`modifierSkillName<n>` / `modifiedSkillName<n>` on the item record, one `Skill_Modifier` record of one level each). The engine check above compares against that sum. A swap adds/removes the items' item skill modifiers (∓ the modifier record's mapped fields) and moves `item_skill_modifiers` for the slot. A learned modifier's level change applies its record delta while its parent contributes, and updates the parent's passive. A linked non-`Skill_Modifier` (transmuter) with mapped stats → warning (`Skill::AddModifierDefenseAttributes` 0x494970 adds only `Skill_Modifier` objects; transmuter class relation not traced) | Possession's AS mod 16 = two dual-wielded b013e swords (`sword1h_b013_possession` 8 each); Witchfire reserve 201 / Life 28 = witchfire1@17 (155) + witchfire2@15 (46, Life 28) |
| granted skills | `itemSkillName` on the removed / added item's records (a grant both carry is no change). Removed: its `item_skills` entry (schema 6, matched by record and `item_id`) — captured char / defense subtracted exactly (the engine adds item skills' collectors to the totals: `SkillManager::GetCharAttributes` 0x52F920 / `GetDefenseAttributes` 0x530C10 walk SkillManager+0x258 while `GetCurrentLevel` != 0), damage % from its record at its level while on; on = captured stats or no weapon flag; a weapon-gated passive with no capture is off and changes nothing. Added: a `Skill_Passive` with no weapon flag (`skill_base.tpl` "Qualifying Weapons"), no pet bonus, a constant `itemSkillLevelEq` and only mapped fields: its record. The score adds an on passive's flat damage to weapon attacks. Everything else → `+? unscored: granted skill X (why)` | tests only (no granted passive in any snapshot; schema 6 not yet captured in game). Every granted `Skill_Passive` with stats in 1.3.1.1 is weapon-gated, so the added side scores none until `Skill::IsQualifyingWeapons` (0x491500) is traced |
| sets | piece count = distinct equipped records per `GetItemSetName` (`GetNumberOfItemsInSet` 0x6A4C0). The set record's bonus at the old and new count (field arrays at min(n − 1, size − 1), 0 pieces = nothing: `ContributeMisc*Attributes` 0x6A6B0…0x6AEE0, `CharAttributeMod::AddToAccumulator` 0xCCA80) is mapped by `gdc::fields` and the delta applied; conversions (`conversionInType/OutType/Percentage`, `…2`) move in the conversion list; augments go through the grant path above; set skill modifiers only while `itemSkillModifierControl` ≥ 1 (`SkillModifierInstall` 0x34B660 → 0x34FB00); the granted `itemSkillName` (level > 0) is reported, not scored. Item stats never include set bonuses, so the score adds the set's flat damage at the equipped count (`gdc::sets`) | no set in any snapshot: tests only (Worldkeeper's Garden 3 ↔ 4, 2 → 1, 3 → 2) |
| modes | `Mode::Engine` (default, calibration): the engine view, a timed buff that is down adds nothing. `Mode::Expected` (tooltip): a down `SkillBuff_Passive` / `Skill_BuffSelfDuration` buff's level delta × uptime (`docs/MECHANICS.md` §6). +levels to a 0-point skill go to `Prediction::unused`, never to the stats; `Skill_Mastery` skills are skipped (the bar takes no item bonus, §6) | store 20261114-172933-952 #1 → #2 passes in Engine mode |

## Warnings ("model inaccurate")

- **Skill level changes not modeled**, per skill: a `Skill_Modifier` whose parent is unknown (schema < 5) or missing, a changed `defensive*` / `character*` field outside `gdc::fields`, a level past the record's array, engine values that differ from the record, a current level that does not follow from level + bonus.
- **Skill activity not in snapshot** (schema < 4): passives and toggles assumed on.
- **All-skills grant changes.**
- **Max resist changes:** `defensive*MaxResist` fields differ. These are `CombatAttributeDefenseCap` entries, which item stats do not show.
- **Set bonuses change:** a piece count changes and the set record is not in the database. Set fields outside `gdc::fields` (e.g. `offensiveSlowPoisonDurationModifier`, `petBonusName`) are listed as `+? unscored: set <field>`.
- **No database:** grants, set bonuses and max resist are not checked.

## Calibration

`gdc_calibrate [DIR] [--char NAME] [--verbose] | --pair A B` (`tools/calibrate`) turns every equipment-only change between two consecutive auto-snapshot records (`store::read`) into a swap test: each changed slot (id, record, component, augment) is swapped in order, then sheet values and each resist's raw / shown are compared with the actual record (integers ±1, resists and regen ±0.1, run speed ±0.001). Pairs with a changed level, difficulty, spent points, an emptied slot or a partial capture are skipped. Exit 0 all pass, 1 a pair fails, 2 usage / read error. Store 20261114-123319-910: ring (b201e → c031) and chest (a11_torso004 → b002e) PASS; fixtures `lvl96-s4-*`.

Output (`calibrate::report`, shared with the adapter): `PASS|FAIL <char> <record> <slot>(<loc>) <old> -> <new>[ (<buff> switched on|off between the snapshots)]`. On a FAIL it is followed by `    <stat>: predicted x, engine y (tolerance t)` and the warnings; `REQ <char> #n <mismatch>` lines report the requirement check.

**Timed buff between snapshots** (`model::toggle_buff`). When a pair fails, each learned timed buff (`SkillBuff_Passive` / `Skill_BuffSelfDuration` reached through `buffSkillName`, uptime < 1) is tried switched on (or off) on top of the swap. The buff's contribution is its record at the current level, plus its learned modifiers at their levels, plus the item skill modifiers attached to it. If one buff explains every diff, the pair passes with that note. Only one buff is tried at a time (shortcut). Evidence: winterpoison #21 → #22 and #35 → #36 (feet swaps) failed with OA +26, regen 26 × 1.24, Aether → Poison 100% and Elemental → Poison 45%. All of it is Blood of Dreeg cast between the snapshots: `bloodofdreeg1_buff` plus the necklace_b001 modifier (crit +15%, Elemental / Aether → Poison). Both pairs now PASS; fixtures `lvl15-wp-before-feet` / `lvl15-wp-after-feet-dreeg-on`.

**Passive calibration** (adapter 0.8.2, `adapter/src/calibration.cpp`). The writer thread runs `calibrate::check` on every auto-snapshot record against the previous record of its chain, plus `calibrate::requirements`. Each `PASS` / `FAIL` block and each new `REQ` line is appended to `GDCompare.calibration.txt`. The file gets a session header and is rotated to `.old.txt` at load when over 2 MB. Skipped pairs only go to the log. While the session has any FAIL or REQ, the tooltip shows `! calibration: N failed this session`. A fault turns calibration off; the rest of the adapter keeps running.

## Not modeled yet

- Requirements are the engine's own values and check (`docs/MECHANICS.md` §7), not recomputed from `itemcostformulas_*`; an item the swap leaves unequippable is taken off once per round (at most 4). Its own set-count change is scored, not listed.
- Conditional stats; skill stats other than through item skill grants and buff uptime (procs: `gdc::effects`).
- Run speed cap.
- Rings: the caller picks the finger.
- Unequipping (an emptied slot): calibration skips it.
